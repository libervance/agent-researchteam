0.13.0: 개인 연구실의 연구팀을 논문·보고서 연구팀(다섯 역할)으로 바꾼 Windows 설치 마법사입니다. 로컬 서버·Hermes 설치·관리자용·사용자용 마법사는 그대로입니다.

- 연구팀: 총괄(research-lead)·조사(research-librarian)·분석/실험(research-experimenter)·감사/심사(research-reviewer)·집필(research-writer). 이전 관리·조사·분석·감사 역할에 논문 원고를 쓰는 집필 역할이 더해졌습니다.
- 총괄이 사용자와 대화하며 논문마다 있는 git 작업 보드에 일을 배정하고, 역할별 실행기가 각자 작업을 가져가 실행합니다. 진행 상황은 각 담당 봇이 같은 스레드에 올립니다.
- 시나리오: 감사를 거친 보고서(Word 첨부), 논문 시작(범위·주장·개요 확인 후 집필), 심사 라운드(블라인드 심사 3건·인용 검증·의장 종합), 사전 등록·승인된 실험 실행과 판정, 제출 전 점검.
- 심사·감사는 작성 과정과 git 기록이 없는 사본에서 진행하고, 각 결과는 읽은 버전(commit)과 함께 기록됩니다. 승인된 실험 계획은 수정할 수 없습니다.
- 이전 분배 서비스의 장치를 옮겼습니다: 설치 파일·프로필 지침의 SHA-256 대조, 해시를 이어 가는 추가 전용 작업 기록, 일시적 모델 오류 재시도, 작업 시간 한도, 결과 파일 업로드 후 재다운로드 SHA-256 비교, 실제 다섯 역할 설치 테스트.
- 모델 라우터(LiteLLM 1.105.1, 이 PC에서만 접근): Anthropic·OpenAI API 키와 선택적 로컬 모델로 역할별 모델을 고르고, 논문의 공개 등급(public / private / air-gapped)에 따라 클라우드·로컬을 나눕니다. 로컬 모델이 없으면 비공개 논문은 보류합니다. Codex 직접 연결도 선택할 수 있으며 이때는 공개 논문·보고서만 처리합니다.
- 이전 4역할 연구팀이 있는 PC는 전환 동의 후 진행 중 작업 종료를 확인하고 설정을 백업한 뒤 바꿉니다. research-lead·research-reviewer는 기록을 유지한 채 이어받고, research-scout·research-worker는 그대로 둡니다.
- 원고 PDF 빌드에는 TeX(MiKTeX 또는 TeX Live)가 필요합니다. 없으면 집필 작업의 빌드가 이유와 함께 보류됩니다.

미서명 Windows x64 빌드입니다. 각 ZIP의 FILES.sha256과 전체 ZIP의 SHA256SUMS.txt를 제공합니다. 실제 Windows PC에서의 전체 설치·실제 모델 테스트는 각 PC에서 마법사의 설치 테스트로 확인합니다. 감사·심사 통과는 사실의 절대적 보증이나 사용자의 최종 승인을 뜻하지 않습니다.

0.12.1: 검색 기록 전달과 감사·재작업 복구를 보완한 Windows 설치 마법사입니다.

- 실제 검색어·실행 순서·시각·제공자 주소·검색 결과를 감사와 재작업 단계에도 전달합니다. arXiv API 변환 주소와 사용자가 지정한 원래 검색어를 구별합니다.
- 반려 후 원본별·감사 단계별로 한 번만 실행 근거를 다시 대조합니다. 실제 결함은 담당자가 수정하고 새 버전을 재감사하며, 프로그램이 감사 통과를 만들지 않습니다.
- 대기 안내처럼 짧은 미완료 결과물과 열람 근거 URL이 없는 조사 결과물은 저장 전에 보완 요청합니다. 같은 원문 중복 열람은 막고 기존 검색 결과를 재작업에도 사용할 수 있습니다.
- 수정 횟수 한도 초과를 구체적인 한국어 사유로 표시합니다. 실패 요청의 한도를 자동 초기화하지 않습니다.
- 종합 중간 감사 전에 실제 Word 후보 파일을 생성해 원문·버전·해시·추출 텍스트를 대조합니다. 최종 감사 뒤 동일한 바이트만 전달해, 파일 생성과 감사가 서로를 기다리는 문제를 해결합니다. 페이지 배치의 시각 검증을 의미하지는 않습니다.
- 설치 실제 테스트는 지정한 첫 검색어로 RAG 논문 최대 2편을 조사하고 중간·최종 감사 및 Word 다운로드 검증까지 수행합니다.

- Research: 개인 연구실용 4역할 설치 마법사. 총괄 계획 → 조사 → 중간 감사 → 분석 → 중간 감사 → 총괄 종합 → 중간·최종 감사 → Word 첨부를 프로그램이 진행합니다.
- 여러 줄 과제의 모델 응답 규격 오류를 수정했습니다. 일시적 모델 오류와 복구 가능한 형식 오류는 2·5·10초 간격으로 최대 3회 재시도합니다.
- 보고서는 기본적으로 .docx 파일로 같은 Mattermost 스레드에 첨부됩니다. 실제 다운로드 해시 검증까지 설치 테스트에 포함합니다.
- 봇 간 응답은 멘션이 있을 때만 이루어지고, 관리 에이전트만 다른 봇의 답변을 자동 관찰합니다.
- User ZIP은 연구원 PC용, Admin ZIP은 별도 서버 관리자용입니다. 개인 연구실은 Research ZIP을 압축 해제한 뒤 Start-HermesResearchSetup.cmd를 실행하세요.

미서명 Windows x64 빌드입니다. 각 ZIP의 FILES.sha256과 전체 ZIP의 SHA256SUMS.txt를 제공합니다. 검색 서비스의 차단·장애, 인증 오류, 사용 한도 초과는 보류될 수 있습니다. 감사 통과는 사실의 절대적 보증이나 사용자의 공식 최종 승인을 뜻하지 않습니다.

학술 자료는 검색어에 site:arxiv.org 를 포함하면 공식 arXiv API로 검색합니다. 반환된 초록 메타데이터는 원문 열람으로 세지 않으며 read_web을 별도로 실행해야 합니다. 일반 웹 검색의 장애·차단이 해소되었다는 뜻은 아닙니다. API 안내: https://info.arxiv.org/help/api/user-manual.html
